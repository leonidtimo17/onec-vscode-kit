# onec-vscode-kit

Любая база 1С:Предприятие 8.3 — в проект для разработки в VS Code одной командой.

`v8dev.py` выгружает конфигурацию и расширения базы в XML-исходники, создает git-репозиторий,
настройки VS Code и подсказок BSL, а также файл правил проекта для ИИ-ассистента: какая
конфигурация, на поддержке ли она, какие модули закрыты, куда можно загружать изменения.

## Возможности

- Базы из списка запуска 1С (`ibases.v8i`) — по номеру или имени.
- Серверные (`Srvr`/`Ref`) и файловые базы, а также базы, доступные только через веб-публикацию, —
  по файлу конфигурации `.cf` (+ `.cfe` расширений): инструмент создает локальную копию и выгружает ее.
- Подбор версии платформы под базу: для серверной базы клиент должен совпадать с сервером.
- Роль базы: рабочая (только чтение) или тестовая/разработка.
- Учетка 1С хранится отдельно для каждой базы в `~/.1c_cred/<база>` с правами 600 — не в проекте и не в git.
- Поиск закрытых (зашифрованных поставщиком) модулей.
- Инкрементальное обновление выгрузки (`refresh`).
- Файлы 1С хранятся в git байт в байт: BOM и CRLF не преобразуются.
- Повторный запуск безопасен: сделанное пропускается, правленые файлы не перезаписываются.

## Требования

- macOS или Windows (Linux — не проверялся), Python 3.8+, git.
- Полный клиент 1С:Предприятие 8.3 с Конфигуратором (тонкого клиента недостаточно).
- VS Code.
- Сетевой доступ к серверу 1С для серверных баз.

## Быстрый старт

```bash
git clone https://github.com/leonidtimo17/onec-vscode-kit.git
cd onec-vscode-kit

python3 v8dev.py check          # платформы 1С, VS Code, скилы
python3 v8dev.py list           # базы из списка 1С и какие можно выгрузить
python3 v8dev.py init 3         # проект из базы №3 списка
```

Проект появится в `~/Documents/1c-dev/<имя базы>/`. Откройте папку в VS Code.

## Команды

| Команда | Что делает |
|---|---|
| `v8dev.py list` | Базы из списка запуска 1С и пометка, какую можно выгрузить |
| `v8dev.py init <номер\|имя>` | Проект из базы списка |
| `v8dev.py init --server SRV --ref REF` | Проект из серверной базы |
| `v8dev.py init --file ПУТЬ` | Проект из файловой базы |
| `v8dev.py init --cf ФАЙЛ.cf [--cfe РАСШ.cfe] --name ИМЯ` | Проект из файла конфигурации |
| `tools/v8dev.py refresh` | В папке проекта: дозагрузить изменения из базы |
| `v8dev.py check` | Проверить окружение |

Параметры `init`: `--role dev|test|prod`, `--dir ПАПКА`, `--v8 ПУТЬ_К_1cv8`, `--cred-file ФАЙЛ`,
`--no-dump`, `--no-setup`.

## Структура проекта

```
<имя базы>/
├── config/                  выгрузка основной конфигурации
├── extensions/<Имя>/        выгрузка расширений
├── CLAUDE.md                правила проекта для ИИ-ассистента (имя файла задано ассистентом)
├── .v8-project.json         реестр базы: платформа, подключение, файл учетки
├── .bsl-language-server.json
├── .vscode/                 кодировка .bsl, рекомендованные расширения
└── tools/
    ├── v8dev.py             refresh
    └── v8run.py             запуск скриптов с учеткой базы, пароль маскируется в выводе
```

## Базы через веб-публикацию

Конфигуратор не подключается к базе через веб-публикацию (`ws="http://…"`) — это ограничение платформы.
Варианты:

1. Прямой адрес сервера 1С и имя базы у администратора: `init --server SRV --ref REF`.
2. Файл конфигурации: администратор сохраняет `.cf` в Конфигураторе (Конфигурация → Сохранить
   конфигурацию в файл), расширения можно сохранить и через веб-клиент (Все функции → Управление
   расширениями конфигурации → Сохранить в файл). Затем `init --cf conf.cf --cfe ext.cfe --name ИМЯ`.

## Подсказки и проверка кода в VS Code

Ставится расширение [Language 1C (BSL)](https://marketplace.visualstudio.com/items?itemName=1c-syntax.language-1c-bsl)
со встроенным BSL Language Server: ошибки и замечания, автодополнение, переход к определению, поиск вызовов.
Настройки — `.bsl-language-server.json`: сообщения на русском, проверка при сохранении, типовые объекты на
поддержке не проверяются.

## Сторонние компоненты

Код набора в этот репозиторий не входит. Отключить установку — `--no-setup`.
