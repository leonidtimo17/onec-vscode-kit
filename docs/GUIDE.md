## 1. Как это устроено

Доработки делаются в XML-исходниках, выгруженных из базы. Ассистент пишет код в VS Code, а в базу 1С
он попадает пакетным запуском Конфигуратора. Типовую конфигурацию на поддержке не меняем — все
доработки в расширениях.

| Что | Где | Зачем |
|---|---|---|
| Проект | `~/Documents/1c-dev/<база>/` (git) | Все, что открывается в VS Code |
| Основная конфигурация | `config/` | Справочник: какие объекты, реквизиты и методы есть |
| Расширения | `extensions/<Имя>/` | Здесь пишется код |
| Правила для ассистента | `CLAUDE.md` в корне проекта | Ассистент читает их при каждом запуске |
| Учетка 1С | `~/.1c_cred/<база>` (вне проекта, не в git) | Подставляется скриптом `tools/v8run.py` |
| Тестовая база | роль `test` или `dev` | Куда загружаем и где проверяем |
| Рабочая база | роль `prod` | Только чтение; готовое переносится вручную |

Ассистент ищет нужное в выгрузке, пишет и проверяет код, загружает его в тестовую базу и проверяет
компиляцию. Решение «работает ли» принимает человек в режиме Предприятия.

```mermaid
flowchart LR
    A[Правка кода<br/>ассистент] --> B[Загрузка в тест<br/>с разрешения]
    B --> C[Проверка в 1С<br/>человек]
    C --> D{Работает?}
    D -- нет --> A
    D -- да --> E[Коммит и .cfe]
    E --> F[Рабочая база<br/>админ, с бэкапом]
```

## 2. Подготовка рабочего места

1. **Платформа 1С 8.3 с Конфигуратором.** Тонкого клиента недостаточно. Для серверной базы версия
   клиента должна совпадать с версией сервера.
2. **Доступ к серверу 1С.** Если Конфигуратор падает с «nodename nor servname provided» и в тексте
   ошибки есть `server_addr=<имя>` — сервер отвечает своим сетевым именем, которое компьютер не знает.
   Добавьте строку `<IP-сервера> <имя>` в `/etc/hosts` (Windows: `C:\Windows\System32\drivers\etc\hosts`).
3. **VS Code** с расширениями ИИ-ассистента (`anthropic.claude-code`) и
   [Language 1C (BSL)](https://marketplace.visualstudio.com/items?itemName=1c-syntax.language-1c-bsl).
   `v8dev.py init` ставит их сам, VS Code также предложит их из `.vscode/extensions.json`.
4. **Проект:** `python3 v8dev.py list`, затем `python3 v8dev.py init <номер>`. Логин и пароль 1С
   спрашиваются один раз и хранятся в `~/.1c_cred/<база>` с правами 600.
5. **Открыть папку проекта** в VS Code и панель ассистента.

Пароль не пишем в чат ассистента и в файлы проекта: история чата хранится на диске.

## 3. Подсказки и ошибки синтаксиса в VS Code

Их дает расширение Language 1C (BSL) со встроенным BSL Language Server; Java не нужна.

1. Откройте папку проекта и любой `.bsl`. При первом открытии расширение скачает BSL Language Server
   и проиндексирует конфигурацию — на большой типовой это несколько минут.
2. После этого работают:
   - ошибки и замечания — вкладка Problems (`Cmd+Shift+M` / `Ctrl+Shift+M`);
   - автодополнение — `Ctrl+Space`;
   - переход к определению — `F12`, поиск вызовов — `Shift+F12`;
   - структура модуля (Outline) и форматирование.

Настройки — `.bsl-language-server.json` в корне проекта: сообщения по-русски, проверка при сохранении,
типовые объекты на поддержке не проверяются (иначе тысячи замечаний по коду поставщика).

Это не замена проверке в платформе: типы и наличие реквизитов в базе окончательно проверяет только
загрузка в тестовую базу.

## 4. Как ставить задачи ассистенту

Пишите задачу обычными словами, как коллеге-программисту: что должно происходить, где и как проверить.

Хорошо:

> В расширении «Интеграция»: при проведении чека ККМ с оплатой сертификатом списывай его во внешнем
> сервисе. Если сервис недоступен — чек не проводить и показать кассиру причину. Проверю на тестовой кассе.

Плохо: «почини сертификаты» — непонятно, что сломано и как должно быть.

- Откройте модуль и выделите кусок кода — ассистент видит выделение.
- Правки показываются как diff: можно принять или отклонить.
- Перед загрузкой в базу ассистент спрашивает разрешение (это правило записано в `CLAUDE.md`).

Команды скилов 1С (набрать `/` в чате ассистента). Обычные слова работают не хуже, команда нужна,
чтобы назвать действие точно:

| Команда | Что делает |
|---|---|
| `/1c-db-dump-xml` | Обновить выгрузку из базы (конфигурация или расширение) |
| `/1c-db-load-xml` | Загрузить исходники в тестовую базу |
| `/1c-db-update` | Обновить конфигурацию БД после загрузки |
| `/1c-db-dump-cf` | Выгрузить расширение в файл `.cfe` (для переноса в рабочую) |
| `/1c-cfe-borrow` | Заимствовать объект типовой в расширение |
| `/1c-cfe-patch-method` | Перехватить метод: до, после или вместо оригинала |
| `/1c-cfe-validate` | Проверить расширение без платформы |
| `/1c-meta-info` | Структура объекта: реквизиты, табличные части, формы |
| `/1c-query-validate` | Проверить запрос: есть ли таблицы и поля |
| `/1c-code-review` | Ревью кода по каталогу типичных ошибок |
| `/1c-config-router` | Подсказать, чем решать задачу |

## 5. Цикл разработки

Одна задача — один круг из шести шагов; если на проверке что-то не так, возвращаемся к шагу 3.

1. **Обновить выгрузку**, если кто-то менял базу в Конфигураторе: `python3 tools/v8dev.py refresh`
   или попросить ассистента. Иначе папка и база разойдутся.
2. **Поставить задачу** ассистенту.
3. **Ассистент ищет и пишет:** находит объекты в `config/`, заимствует их в расширение, пишет
   перехватчики и модули в `extensions/<Имя>/`.
4. **Ассистент проверяет без платформы:** структуру расширения, имена в запросах, вызовы общих модулей.
5. **Загрузка в тестовую базу и проверка** — следующий раздел.
6. **Коммит** с описанием задачи. В git остается история, к любой версии можно вернуться.

Если правите руками в Конфигураторе (например, форму мышкой) — сразу после этого обновите выгрузку
(шаг 1), иначе следующая загрузка из папки затрет вашу правку.

## 6. Запуск после разработки

Готовое расширение проходит три этапа: загрузка в тестовую базу (ассистент), проверка в Предприятии
(человек) и перенос в рабочую базу (вручную, администратор). В рабочую базу ассистент не ходит.

### Этап 1. Загрузка в тестовую базу

1. Закройте Конфигуратор тестовой базы. Режим Предприятия можно не закрывать.
2. Попросите ассистента: «загрузи расширение <Имя> в тестовую базу и проверь модули». Он спросит
   подтверждение.
3. Ассистент загружает исходники из `extensions/<Имя>/`, обновляет конфигурацию БД и запускает
   проверку модулей. Ошибки компиляции он видит сам, исправляет и загружает снова.
4. Результат: «загружено, ошибок нет» или список того, что не собралось.

### Этап 2. Проверка в Предприятии

1. Запустите 1С:Предприятие → тестовая база. Если сеанс был открыт — перезайдите: расширение
   применяется только к новым сеансам.
2. Все функции → Стандартные → Управление расширениями конфигурации: расширение есть и активно.
   Расширению, которое ходит в интернет, нужен снятый флажок «Безопасный режим».
3. Пройдите сценарий задачи целиком, включая ошибочные ветки (нет связи, возврат и т.п.).
4. Что-то не так — опишите ассистенту или пришлите скриншот ошибки. Он поправит и загрузит заново.
5. Все работает — коммит.

### Этап 3. Перенос в рабочую базу

Расширение ставится из режима Предприятия файлом `.cfe` — так работает и для баз через
веб-публикацию. Нужны права администратора.

1. **Файл:** попросите ассистента «выгрузи расширение <Имя> из тестовой базы в cfe». Он положит файл
   в `build/` проекта — это именно та версия, которую вы проверили.
2. **Время:** нерабочее или с предупреждением пользователей. Пользователям придется перезайти, а если
   расширение добавляет реквизиты или регистры — база может потребовать монопольный режим.
3. **Резервная копия:** в рабочей базе Все функции → Стандартные → Управление расширениями
   конфигурации → выбрать расширение → «Сохранить в файл». Это ваш откат.
4. **Установка:** там же — «Обновить из файла» (для нового расширения — «Добавить из файла») →
   выбрать `.cfe` из шага 1. Проверить флажки «Активно» и «Безопасный режим», как в тестовой.
5. **Проверка:** перезайти и прогнать короткий сценарий.
6. **Откат, если что-то сломалось:** «Обновить из файла» с резервной копией из шага 3 или снять
   «Активно» и перезайти.

## 7. Правила и частые ошибки

Три правила без исключений:

- Типовую конфигурацию не меняем — только расширения. Иначе следующее обновление от поставщика сотрет
  правки или не встанет.
- В базу — сначала тестовая, потом рабочая, и только та версия, что прошла проверку.
- Пароли — только в `~/.1c_cred/`, не в чат и не в файлы проекта.

| Симптом | Причина | Что делать |
|---|---|---|
| «Ошибка блокировки информационной базы для конфигурирования» | Открыт Конфигуратор этой базы | Закрыть Конфигуратор и повторить |
| «nodename nor servname provided», `server_addr=<имя>` | Компьютер не знает сетевое имя сервера 1С | Строка `<IP> <имя>` в hosts |
| «Пользователь ИБ не идентифицирован» | Неверный логин или пароль | Удалить `~/.1c_cred/<база>` и запустить `init` снова |
| Изменения не видны в Предприятии | Старый сеанс | Перезайти в базу |
| Расширение не ходит в интернет | Включен «Безопасный режим» | Снять флажок в Управлении расширениями |
| Ручная правка в Конфигураторе пропала | После нее загрузили старую версию из папки | После ручных правок сразу `refresh` |
| Загрузка расширения висит без вывода | Известная особенность 8.3.27: права роли на новое перечисление | Загрузка в два прохода: сначала без роли |
| Конфигуратор не открывает базу через веб-публикацию | Ограничение платформы | `init --server/--ref` или `init --cf` (см. README) |
